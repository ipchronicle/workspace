## 验证范围

候选工作流全部 44 项任务成功，覆盖源码检查、浏览器、Compose、产物校验、
34 个发行版与架构组合、失败恢复、稳定版升级、双架构资源与可复现构建。

稳定升级测试使用固定 `v0.1.1` 源码提交
`9ecd98779546514b043032f4b98f55d77054a8c5` 生成合成数据，再由新版本读取。
验证配置原有记录、历史、管理员登录、主密钥、节点身份与凭据、代理秘密，以及
Agent 原状态、API Key 和离线结果确认出队。测试没有使用真实生产数据或凭据。

资源测试在 Agent 64 MiB、Center 512 MiB 容器限制下完成真实探测，未出现 OOM：

| 架构 | Agent 空闲 RSS（KiB） | Agent 峰值（字节） | Center 峰值（字节） |
| --- | ---: | ---: | ---: |
| AMD64 | 17176 | 63045632 | 169451520 |
| ARM64 | 15428 | 62636032 | 157487104 |

这些数据描述验收负载，不代表任意节点规模与网络响应下的内存保证。

JavaScript 通知 worker 的正常 HTTP 调用曾触发原 128 MiB data segment 上限。
进程诊断显示运行时映射和原生线程预留已经占用大部分额度。现行实现使用 256 MiB
硬上限及 64 MiB Go 内存回收软目标，保留隔离进程、期限和超量分配终止。正常 HTTP
请求重复执行、超量分配和发布浏览器测试通过。测试只向隔离的本地接收端发请求。

## 升级与回滚

先升级 Center，再更新 Agent。升级前停止 Center，一致备份 `./data/config` 和
`./data/history`；保留各节点的 `/var/lib/ipchronicle-agent`。

Center 通过新有序迁移保留 `v0.1.1` 配置、主密钥、历史、节点身份和凭据引用，
没有重写已发布迁移。Agent 状态 schema 仍为 9，离线队列继续可读。
两种官方 Compose 新增 `./data/logs:/var/lib/ipchronicle/logs`；Cloudflare Tunnel
部署保留对应文件和现有 token。

配置迁移后不支持直接切回旧 Center 镜像。降级需要停止 Center、恢复升级前配套
备份，再运行旧版本；升级后新增的数据不会出现在旧备份中。

同步后复现问题，再按任务、公网 IP、组件和时间筛选日志。ipapi 检查 HTTP 状态、
限流响应头、失败正文及重试结束原因；NAT 与目标问题关联发现、同步和任务日志。
分享第三方失败正文前检查敏感内容，采集结束恢复 `info`。
