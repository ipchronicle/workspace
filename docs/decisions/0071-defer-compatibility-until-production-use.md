# ADR 0071：在版本投入正式使用后建立数据兼容基线

Status: Superseded by ADR 0072

Date: 2026-09-04

Supersedes: ADR 0068

## 背景

`v0.1.0` 已作为公开 GitHub Release 发布，但没有部署到需要保留数据的正式环境。
ADR 0068 将“公开发布”误认为“已经投入使用”，因而把 `v0.1.0` 的 Center 数据库
和 Agent 状态定义成了持久数据兼容基线。

项目仍在调整首个正式部署所需的运行和部署边界。此时为没有实际数据的版本维护
升级迁移，会增加未经真实需求验证的兼容代码和发布测试，也会妨碍直接修正早期
设计。

## 决策

- `v0.1.0` 没有建立配置库、历史库、Agent 状态或 Compose 数据布局的兼容承诺。
- 当前没有需要支持的持久数据升级来源。开发、测试、RC 和尚未投入正式使用的
  stable Release 数据均可在格式变化后干净重建，不为其增加迁移、双读双写或旧
  格式回退。
- Git tag、GitHub Release、版本号或镜像发布不单独构成数据兼容基线。项目负责
  人明确确认某个版本已部署到需要保留数据的正式环境后，该版本的数据格式才成为
  首个兼容基线。
- 建立兼容基线时必须记录确切版本、受保护的持久数据范围和最低升级测试要求。
  此后的格式变化遵守 ADR 0023、0025 和 0026 定义的迁移、Agent 回滚及发布门禁。
- 尚无兼容承诺不允许静默伪造成功。不兼容的开发数据应明确报错或由操作者执行
  干净重建。

## 后果

- `v0.1.1` 可以直接采用目录挂载的 Compose 数据布局，无需迁移 `v0.1.0` 的
  Docker named volumes。
- 首次正式上线前可以继续清理持久格式和迁移基线，不保留仅服务于未使用版本的
  分支。
- 正式环境一旦确认投入使用，后续版本就必须承担从已记录基线向前升级的兼容成本。

## 备选方案

### 继续以 v0.1.0 作为兼容基线

未采用。该版本没有需要保留的正式环境数据，兼容工作不会保护实际用户状态。

### 永远不承诺升级兼容

未采用。个人自托管用户仍然需要在正式使用后可靠保留账户、节点、凭据、历史和
Agent 离线状态；延后基线不等于取消兼容责任。
