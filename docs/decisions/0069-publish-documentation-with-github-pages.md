# ADR 0069：使用独立 GitHub Pages 仓库发布在线文档

状态：已接受

日期：2026-09-03

## 背景

IPChronicle `v0.1.0` 发布后，产品仓库已经提供中英文 README、运维指南、通知
说明、版本说明和发布就绪报告。这些 Markdown 文件适合随源码标签和发布资产冻结，
但缺少面向使用流程的导航、站内搜索、稳定链接和明确的语言切换。

GitHub Pages 的组织根站点要求源码来自名为
`ipchronicle/ipchronicle.github.io` 的仓库。将站点放进产品仓库只能使用
`/ipchronicle/` 项目路径；将生成文件推入专用分支则会把构建产物历史与可审查的
文档源码混合。

## 决策

- 创建公开仓库 `ipchronicle/ipchronicle.github.io`，发布到
  `https://ipchronicle.github.io/`。
- 文档站使用 VitePress 和 GitHub Pages。仓库只提交 Markdown、站点配置、必要
  静态资产和依赖锁文件，不提交构建输出。
- 简体中文位于站点根路径，英文位于 `/en/`。两个语言版本使用相同的相对页面
  结构，并在同一变更中维护；不根据浏览器语言自动跳转。
- 站点根路径描述最新稳定版，不把未发布行为写成稳定功能。需要同时支持具有不同
  操作流程的多个版本时，再决定站内版本选择机制。
- 在线站点负责最新稳定版的分章节使用、安装、运维和故障排查指南。产品仓库继续
  保存 README、版本说明、发布就绪报告，以及随每个 Release 冻结的离线运维和
  通知文档。冻结文档属于发布证据，不由在线站点替代。
- workspace 继续保存产品定义、架构基线和 ADR。文档站可以链接这些记录，但不
  复制其全文或成为架构决定的第二来源。
- `.github` 仓库继续保存组织首页和公共协作文件。文档站不另设 Issue 入口，文档
  问题统一进入产品仓库。
- Pull Request 必须通过中英文页面配对、内部链接和静态构建检查。`main` 通过后
  使用 GitHub 官方 Pages Actions 发布；构建产物只作为 Pages 部署的短期传输
  artifact，不成为 Release 资产。
- 搜索使用本地索引。首版不加入分析、广告、远程字体或第三方运行时脚本。

## 影响

- IPChronicle 增加一个具有明确独立职责的公开仓库，但 Center、Web、Agent、API、
  部署和发布工具仍留在产品单仓库中，ADR 0022 的产品源码边界不变。
- 产品行为或运维流程变化可能同时需要产品仓库和文档仓库提交。在线文档与稳定
  版本不一致时必须作为发布阻塞问题处理，不能用自动抓取未发布主分支来掩盖。
- 用户获得中文默认、英文可切换、可搜索且具有稳定根域名的在线文档；特定旧版本
  仍可从 Git 标签或 Release 获取冻结文档。

## 考虑过的替代方案

### 从产品仓库发布项目 Pages

没有采用。它能让代码和文档在同一提交中演进，但默认地址为
`https://ipchronicle.github.io/ipchronicle/`，不能提供组织根站点。

### 创建只负责跳转的组织站点

没有采用。它增加仓库和部署流程，却没有提供导航、搜索或更好的文档体验。

### 使用 Docusaurus

没有采用。它内置更完整的多版本功能，但当前只维护一个稳定版，依赖和配置成本
超过现阶段需求。

### 使用 MkDocs Material

没有采用。其文档体验成熟，但会引入新的 Python 构建工具链和多语言插件配置；
VitePress 已满足当前 Markdown、双语、本地搜索和静态发布需求。
