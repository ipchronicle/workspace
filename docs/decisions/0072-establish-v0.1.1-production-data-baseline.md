# ADR 0072：将 v0.1.1 设为首个生产数据兼容基线

Status: Accepted

Date: 2026-09-04

Supersedes: ADR 0071

## 背景

ADR 0071 规定，公开发布本身不建立持久数据兼容承诺；只有版本实际投入需要保留
数据的正式环境后，才能确定兼容基线。`v0.1.0` 没有进入这样的环境，因此不属于
受支持升级来源。

项目负责人已经确认 `v0.1.1` 于 2026-09-04 正式上线，其 Center 和 Agent 开始
产生需要在后续升级中保留的真实运行数据。

## 决策

- `v0.1.1` 是 IPChronicle 的首个持久数据兼容基线。
- Center 兼容范围包括 `config.db`、与其匹配的 `master.key`、`history.db`，以及
  Compose 安装目录中的 `./data/config` 和 `./data/history` 数据布局。
- Agent 兼容范围包括各节点的 `/var/lib/ipchronicle-agent`，其中的节点身份、
  凭据、已应用配置、地址状态、离线队列、探测状态和更新状态必须在受支持升级与
  失败回滚中保持有效。
- Center 配置中的管理员账户、有效期内会话、节点身份与设置、注册状态、代理和
  通知凭据引用、计划、任务状态及历史代次必须保留。历史库中的地址事件、完整
  探测运行、执行、快照、变化状态和缺口记录必须保留，除非操作者明确执行产品
  提供的历史清理操作。
- `v0.1.1` 标签、发布产物、Center 镜像、初始迁移和 Agent 状态格式是该基线的
  权威实现来源。已经发布的迁移不得重写；后续 Center schema 变化使用新的有序
  前向迁移。
- 后续同一主版本的受支持升级必须从 `v0.1.1` 和所有仍受支持的后续稳定 schema
  状态验证。测试使用固定旧版本夹具或对应发布产物生成状态，不得使用当前版本的
  序列化代码伪造旧格式。
- Agent 状态变化和更新失败回滚遵守 ADR 0023，Center 迁移遵守 ADR 0025，升级
  与发布门禁遵守 ADR 0026 和 ADR 0070。
- `v0.1.0`、开发版和 RC 数据继续排除在受支持升级路径之外。能够偶然读取这些
  数据不构成兼容承诺，也不能成为保留永久兼容分支的理由。
- 损坏、来自未来版本或不受支持的状态必须明确失败。启动和升级流程不得静默
  删除、重建、替换、降级或重新解释稳定版数据。

## 后果

- `v0.1.1` 之后修改数据库或 Agent 持久格式时，迁移、回滚边界、旧版本夹具和
  升级测试属于实现的一部分。
- 不能再通过清空 Center 配置目录、重置 Agent 状态或重写初始迁移来简化正常
  升级。历史数据仍可由操作者通过既定的独立清理功能主动删除。
- 兼容承诺不等同于内置备份功能。服务器操作者仍负责在需要回滚或灾难恢复时
  一致保存 Center 数据目录和相关 Agent 状态。

## 备选方案

### 继续延后兼容基线

未采用。`v0.1.1` 已经产生需要保留的正式环境数据，继续按可丢弃开发数据处理会
使正常升级存在实际数据丢失风险。

### 只保护 Center 配置

未采用。历史记录和 Agent 本地身份、离线队列及更新状态都是核心运行数据，只
保留配置无法维持节点连续性、历史比较和故障恢复。

### 同时兼容 v0.1.0 和预发布数据

未采用。这些版本没有进入需要保留数据的正式环境，为其增加迁移不会保护真实
用户状态，只会扩大长期维护和测试成本。
