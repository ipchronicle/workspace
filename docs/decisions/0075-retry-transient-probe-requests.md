# ADR 0075：对第三方探测请求执行有界重试

Status: Accepted

Date: 2026-09-05

Amends: ADR 0063

## 背景

第三方数据源的短时网络故障和服务错误可能导致报告缺值。请求重试需要保持原有
查询目标、出口、请求内容和报告语义，并与任务超时、通知投递及离线结果上传分别管理。

## 决策

- 完整探测中的 HTTP GET、HEAD 请求使用共同重试机制。ipapi 和 DB-IP 的只读
  POST 查询显式允许重放；创建媒体会话等其他 POST 保持单次请求。
- 每次查询最多发起三次应用层尝试。两次等待分别以一秒、三秒为基准，各增加
  小于 500 毫秒的随机延迟。
- 暂时性 DNS 错误、超时、连接拒绝或重置、连接提前结束，以及 HTTP 408、429、
  500、502、503、504 可以重试。证书、永久 DNS、认证、权限、参数和超大响应
  错误直接交给原有结果处理。
- `Retry-After` 支持秒数和 HTTP 日期，实际等待至少满足服务端要求，再加入随机
  延迟。等待超出任务剩余时间时结束该查询，保留失败结果与日志。
- 结构化错误明确包含已识别的日/月请求额度耗尽或余额不足信息时，429 直接结束。
  未识别的 429 采用有界重试，保留失败正文用于诊断。
- HTTP 成功响应中的空字段、无效 JSON 和业务错误不触发通用重试。媒体探测继续
  按数据源规则解释屏蔽、地域限制等结果。
- 每次尝试继续使用十秒请求超时和 4 MiB 响应上限，所有尝试共享完整探测的既有
  十五分钟期限。任务取消立即终止请求或等待，不重新启动整项探测。
- 请求层作为应用层重试的唯一所有者。探测数据源不再叠加独立重试循环；通知、
  注册、更新下载、轻量发现和离线上传不受本决策调整。
- 既有结构化日志关联节点、任务、IP 和失败类别。消息记录尝试次数、下一次等待、
  重试耗尽或取消原因；保持请求凭据脱敏和失败正文按需查询的边界。

## 后果

临时失败可能恢复；持续故障会增加查询耗时和第三方请求量，但受次数和任务期限
约束。重试不能保证解决共享 Key 的额度限制，也不能作为 ipapi 缺值根因已确认的
依据。实现不需要持久化格式或日志协议变更。

## 备选方案

- 单次请求：实现简单，但瞬时故障直接形成缺值。
- 所有错误统一重试：增加认证、格式和业务错误的请求负担，并可能重复创建会话。
- 中心跨节点调度限流：需要真实额度规则和请求日志作为依据，当前请求层故障恢复
  不引入额外调度服务。
