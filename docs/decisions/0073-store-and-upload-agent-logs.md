# ADR 0073：使用独立日志库和有界 Agent 日志队列

Status: Accepted

Date: 2026-09-04

Partially supersedes: ADR 0010

## 背景

`v0.1.1` 上线后，Agent 对外部服务请求、地址发现、完整探测和配置同步的错误
大多只保留在节点本机，且部分实现会把具体错误折叠成 `no-valid-response`。Center
无法区分 DNS、连接、TLS、超时、限流、HTTP 状态、响应过大或格式错误，也无法
关联任务、公网 IP、代理和内部发现路径。

日志可能包含较大的失败响应，不能与配置或核心历史竞争同一个数据库和离线队列。
节点最多可能长时间离线，因此 Agent 侧也必须明确限制磁盘占用。

## 决策

- Agent 使用同一结构化事件源生成本机人类可读日志和待上报日志。事件等级为
  `error`、`warn`、`info` 或 `debug`；每节点独立配置，新节点默认 `info`。
- 日志等级通过版本化 Agent 配置和能力协商同步。页面筛选只改变显示，不改变
  采集等级；修改等级不删除已经上报的事件。
- 事件可以关联组件、事件类型、任务、公网 IP、地址族、代理、配置 revision 和
  内部发现路径。内部路径只在日志详情中显示，不提升为用户管理对象。
- 外部失败至少区分 DNS、连接、TLS、超时、限流、HTTP 状态、响应过大和响应
  格式错误。所有日志等级保存失败响应的原始正文；成功响应不保存正文。
- 单响应继续受请求层 4 MiB 上限约束。超过上限时保存已接收部分并明确标记截断，
  不能把截断内容描述为完整响应。
- 请求目标移除 userinfo、查询参数和 fragment。请求认证头、请求体、Agent Token、
  注册或恢复密钥、代理密码和 API Key 不进入日志。失败响应正文不做内容级脱敏；
  Center 将其作为不可信文本或字节展示，绝不作为 HTML 执行。
- Agent 在现有 bbolt 状态中维护独立日志队列，最多占用 64 MiB 且最多保留
  10,000 条。达到任一上限时淘汰最旧事件，并在独立缺口元数据中聚合丢失数量及
  时间范围。日志队列不占用探测结果配额，也不能阻塞轮询、发现或探测。
- Agent 使用现有节点凭据向独立批量接口上传日志。每批最多 64 条且编码请求不超过
  8 MiB；事件 UUID 用于幂等确认。上传重试只重传数据，不重新执行探测。
- Center 使用独立 `logs.db`。日志保留支持按天、按逻辑容量和永久保留，默认按天
  保留 7 天。损坏的日志库明确阻止正常启动或打开，不静默重建；操作者可以在
  Center 停止后仅删除日志库而保留配置和历史。
- Center 提供全局日志页和节点详情日志标签。两者共用查询接口与组件，支持时间、
  节点、等级、组件、事件类型、公网 IP、任务、代理和消息关键词筛选；关键词不
  搜索完整响应正文。页面每 5 秒增量刷新，可暂停，查看旧记录或正文时不跳动。

## 后果

- Center 的持久布局增加 `./data/logs/logs.db`，系统状态和保留设置需要单独报告
  日志库状态。
- Agent bbolt schema 必须从 `v0.1.1` 的版本向前迁移，并纳入更新失败回滚测试。
- 日志正文可能包含第三方返回的敏感数据。单管理员自托管模型下由管理员承担查看
  和保留责任，产品仍必须防止其进入 HTML 执行上下文。
- `logs.db` 是可丢弃的运维数据，不参与历史 generation，也不能成为核心状态的
  第二事实来源。

## 备选方案

### 将日志写入 config.db 或 history.db

未采用。高频或大响应日志写满时会影响配置或核心历史，且无法独立清理恢复。

### 只依赖 systemd 或 OpenRC 日志

未采用。管理员无法跨节点筛选，也无法从 Center 关联任务、地址和代理。

### 通过控制轮询携带日志

未采用。大批日志会扩大关键心跳请求，并让日志积压干扰控制平面。
