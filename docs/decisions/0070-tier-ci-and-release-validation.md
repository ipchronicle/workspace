# ADR 0070：分级执行持续集成与发布验证

Status: Accepted

Date: 2026-09-03

Partially supersedes: ADR 0026

Refines: ADR 0017 and ADR 0027

## 背景

IPChronicle 同时发布 Center、Web、Agent、安装脚本和双架构镜像。ADR 0026 为
首个稳定版本定义了完整质量门禁，其中包括竞态检测、浏览器与 Compose 测试、
支持发行版和架构矩阵、资源限制、真实探测、失败恢复及可复现构建。

这些门禁适合建立首个稳定兼容基线，但全部应用到每次日常提交和每个补丁发布会
重复构建相同产物，并让低风险修复承担与主次版本相同的时间和算力成本。另一方面，
完全按版本号跳过测试也不可靠：安装器、迁移或 Agent 状态修复即使以补丁版本发布，
仍可能影响 root 服务、用户数据和离线节点。

## 决策

- 持续集成分为快速 CI 和扩展 CI。快速 CI 是每个非纯文档提交及 Pull Request
  的基础门禁，执行生成文件漂移、格式、Lint、类型、普通单元测试、静态分析、
  秘密扫描及生产 Web 构建，不执行竞态检测和完整发布矩阵。
- Dockerfile、Compose、浏览器工作流及其直接依赖只在相关路径变化时追加对应的
  AMD64 镜像、Compose 或浏览器测试。被新提交取代的同分支运行可以取消。
- 扩展 CI 每周定时运行，也可以手动触发。它执行竞态检测、完整源码构建、
  AMD64/ARM64 镜像、Compose、桌面和移动浏览器流程及确定性失败门禁，作为路径
  分类遗漏和依赖漂移的周期性回归检查。
- 每个正式候选仍从同一源码修订构建并验证 AMD64/ARM64 Center 与 Agent 产物、
  清单、校验和、SBOM、版本和源码修订元数据。发布流程不能上传本地产物。
- `MAJOR.MINOR.0` 及其 RC 自动运行完整发布验证，包括重复构建一致性、全部受支持
  发行版与架构生命周期、资源限制和真实探测，以及 ADR 0026 定义的发布失败门禁。
  这覆盖主版本和次版本发布；在 `v0` 阶段，次版本同样视为完整验证版本。
- `MAJOR.MINOR.PATCH` 且 `PATCH > 0` 的候选使用补丁验证。它在基础候选验证之外，
  根据上一个稳定标签到候选修订的改动路径追加门禁：
  - Agent 安装、更新或服务生命周期变化运行发行版与架构矩阵；
  - 数据库 migration、Agent 状态或恢复逻辑变化运行 Compose、升级和失败恢复门禁；
  - Web、OpenAPI 或管理流程变化运行浏览器门禁；
  - 探测、网络出口、代理或资源边界变化运行资源限制与真实探测门禁；
  - Dockerfile 或部署资产变化运行镜像与 Compose 门禁。
- 找不到可信的上一稳定标签、改动无法分类或发布负责人明确要求时，候选按完整验证
  处理。路径分类只能增加门禁，不能使快速 CI 或候选产物验证变成可选项。
- ADR 0017 的支持矩阵继续定义官方支持范围。补丁版本在安装器、Agent 生命周期和
  支持范围均未变化时可以继承最近一次完整验证证据；相关边界变化时必须重新执行
  矩阵。每份 Release 仍发布适用的支持矩阵。
- GHCR `latest` 只在稳定 GitHub Release 成功发布后指向该版本镜像。主分支、PR、
  定时和其他开发构建不得覆盖 `latest`，也不成为 ADR 0027 的官方更新通道。

## 后果

- 日常修复能在快速反馈后合并，双架构模拟、浏览器和发行版矩阵不再无条件重复。
- 补丁发布耗时取决于实际风险范围，而不是统一承担完整主次版本门禁。
- 路径分类成为发布基础设施的一部分；新增组件或移动目录时必须同步更新分类并通过
  每周扩展 CI 检查遗漏。
- 完整验证证据可能来自最近的主次版本、相关高风险补丁或定时运行，不再要求每个
  无关补丁重复证明所有不变边界。
- `latest` 恢复为稳定版本别名，使用示例 Compose 不会自动部署未发布的主分支代码。

## 备选方案

### 每次提交和每个 Release 执行全部门禁

未采用。它提供最直接的单次证据，但重复构建、QEMU 双架构和发行版矩阵显著延长
低风险修复反馈，实际成本与改动风险不匹配。

### 只有主次版本执行测试，补丁版本只构建

未采用。版本号不能代替风险判断；迁移、root 安装器、Agent 更新和认证修复可能以
补丁发布，却仍需要其所属边界的直接验证。

### 只依赖开发者本地验证

未采用。官方产物需要由可审计的 GitHub Actions 从确切源码修订构建和验证，本地
环境不能作为公开发布门禁的事实来源。
