# v0.1.1 线上问题与后续整改

## 文档状态

- 状态：设计已确认，实施中
- 建立日期：2026-09-04
- 适用基线：已投入线上使用的 `v0.1.1`
- 目的：集中记录首个线上版本暴露的问题、处理优先级、依赖关系、已确认设计和
  实施状态。

本文档是问题整改入口，不替代产品定义、系统架构或 ADR。经确认的长期决定应
同步写入相应权威文档；实现完成后应在本文件中记录验收状态。

## 优先级定义

- **P0：可观测性与结果可信度。** 当前会阻碍线上故障定位，或可能让管理员误判
  探测结果，应优先处理。
- **P1：身份连续性与操作正确性。** 不一定阻塞当前诊断，但会导致历史关联丢失、
  错误导航或高风险误操作。
- **P2：批量效率与界面可理解性。** 改善日常管理效率和信息层级，在 P0、P1
  边界明确后实施。

优先级表示处理顺序，不表示低优先级问题可以长期忽略。

## 建议处理顺序

1. 定义并实现 Agent 日志采集、传输、存储和 Center 查询能力。
2. 使用新增日志复现并定位 ipapi 缺失及公网 IP 发现、NAT 判断和任务目标不一致。
3. 统一报告值语义，修复页面与 PNG 输出；随后处理立即探测确认和返回路径。
4. 定义节点重装恢复身份的凭据和接管规则，并实现稳定版数据迁移与升级测试。
5. 重新定义首页关注项。
6. 实现节点多选及批量操作。
7. 完成临时同步说明、列表降噪和最近报告快速预览。

问题 2、6、7、9 可以与前述设计讨论并行准备，但不能绕过各自的验收要求。

## 已确认的设计

### 1. Agent 日志与中心查询

- Agent 应记录足以定位发现、探测、同步和外部请求失败原因的结构化日志。
- Center 日志属于可丢弃的运维数据，独立存入 `logs.db`，避免日志写满或清理操作
  直接影响 `config.db` 和 `history.db`。
- 日志保留策略支持按天、按总容量和永久保留，默认保留 7 天。
- Agent 离线日志使用独立有界磁盘队列，同时限制为 64 MiB 和 10,000 条。达到
  任一上限时淘汰最旧日志，并聚合记录缺口数量及时间范围。
- 每个节点独立设置 `error`、`warn`、`info` 或 `debug`，新节点默认 `info`。
- 不增加全局日志等级设置；节点多选功能可以为多个节点批量修改等级。
- 日志等级通过现有版本化配置同步，在 Agent 应用新配置后生效。
- Center 页面筛选只影响显示，不改变 Agent 采集等级；切换等级不删除已经上报的
  日志。
- 外部失败至少区分 DNS、连接、TLS、超时、限流、HTTP 状态、响应过大和响应
  格式错误。所有等级保存失败响应的原始正文，成功响应不保存正文；单响应继续受
  当前 4 MiB 请求层上限约束。
- 请求目标移除 userinfo、查询参数和 fragment。请求认证头、请求体、Agent Token、
  注册或恢复密钥、代理密码和 API Key 不进入日志。失败响应正文不做内容级脱敏，
  Center 仅按不可信文本或字节显示，不作为 HTML 执行。
- 日志使用现有 Agent 凭据通过独立接口批量上传，不塞入控制轮询。每批最多 64 条、
  编码请求最多 8 MiB，使用事件 UUID 幂等确认，独立 worker 重试。
- 本机 systemd/OpenRC 日志与上报日志来自同一事件源。日志队列不得阻塞探测、发现
  或控制轮询，也不占用探测结果队列配额。
- 全局日志页和节点详情日志标签共用查询接口与组件。筛选维度包括时间、节点、等级、
  组件、事件类型、公网 IP、任务、代理和消息关键词；关键词不搜索完整响应正文。
  页面每 5 秒增量刷新，可暂停，查看旧日志或正文时不跳动。

持久化影响：Center 新日志库和 Agent 离线缓存都必须通过新迁移或向前兼容的
Agent 状态升级实现，不得修改 `v0.1.1` 已发布的迁移基线。

### 3. 首页“需要关注”

“需要关注”只收录异常、失败或需要管理员采取行动的状态：

- 应在线但已离线的节点；
- 配置同步失败或长时间未应用；
- 在线启用节点的当前公网出口发现失败，按节点聚合且不显示内部路径 ID；
- 当前公网 IP 最近一次完整探测失败或部分失败；
- 内存不足导致完整探测自动暂停；
- Agent 更新失败且目标版本尚未安装；
- 最新报告字段格式异常；
- 已启用通知发送器最新一次最终投递失败；
- 历史保留执行失败或执行后仍超出限制。

以下内容不作为关注项：

- NAT 路径本身；
- 正常的公网地址变化；
- 存在可用 Agent 更新；
- 下一次计划执行时间；
- 管理员主动禁用的节点、代理或公网 IP；
- 不可恢复的日志或历史缺口。

NAT 仍作为公网 IP 的路径信息显示，但不使用告警视觉或占用首页关注列表。异常恢复
后对应关注项自动消失；节点离线时不重复显示配置待同步。同类问题按异常类型聚合，
每类显示准确数量和部分节点，点击进入带筛选的目标页面，不静默截断为固定前几条。

### 4. 节点重装后的身份恢复

节点注册成功后，应提供该节点专属的安装命令。管理员在重装系统后使用该命令，
Agent 应恢复同一节点身份，并继续关联原有配置、历史和公网 IP，而不是创建新节点。

恢复使用独立、长期可用且可轮换的节点恢复密钥，不复用日常 Agent Token 或通用
注册密钥。Center 保存校验摘要和主密钥加密副本，以便再次显示专属命令。恢复成功
不自动轮换；即使旧 Agent 在线，新 Agent 也立即原子接管并撤销旧凭据。

恢复保留节点 ID、名称、启用状态、计划、代理、日志等级、公网 IP 关联和全部 Center
历史；结束旧未完成任务，将已应用配置 revision 重置为 0，并清除旧主机能力、库存、
内存和当前路径状态。已撤销或待删除节点拒绝恢复，禁用节点恢复后仍保持禁用。旧系统
盘上尚未上传的数据不属于 Center 恢复范围。详细安全边界见 ADR 0074。

### 5. 节点多选与批量操作

节点清单的复选框始终显示，多选后提供批量 Agent 更新、完整探测和日志等级修改。
批量操作不是事务：每个节点独立接受、跳过或失败，结果必须逐节点可见。

选择在筛选变化和自动刷新时保留，只有节点从结果中消失才移除；表头选择当前筛选
结果，工具条显示总数和清空操作。批量探测默认包含每个节点全部当前可用公网 IP，
不受周期探测开关影响；确认框可按节点展开并取消个别 IP。离线、禁用、忙碌、低内存
或没有可用 IP 的节点跳过，其余节点继续创建任务。每节点仍只有一个任务槽，不增加
等待队列。

### 8. 返回来源上下文

所有进入详情、快照、比较和日志的站内链接通过 React Router 路由状态携带立即来源。
返回按钮优先回到经过标记的真实应用内历史项，以保留 URL 筛选、分页和滚动位置；
刷新、复制 URL、直接打开或新标签无有效来源时回到语义父页面。来源只接受站内路由，
不使用裸 `history.back()`，也不在 URL 中层层编码 `returnTo`。

### 12. 报告状态语义与 PNG

报告必须区分三个状态：

1. 数据源明确返回肯定结论；
2. 数据源明确返回否定结论；
3. 数据源没有返回结论，即 JSON `null`。

风险因子统一使用“是”和“否”表示明确的布尔结论，JSON `null` 使用中性的“无数据”。
`null` 不能显示成否定结论，也不能被列为格式错误。

页面、PNG 导出、复制 PNG 和通知图片应共享同一套值格式化与状态色规则，避免相同
结果在不同载体中产生不同含义。PNG 导出副本内置 Noto Sans SC，不改变日常页面字体；
导出使用固定桌面报告宽度、明确行高和嵌入字体，验证中文、英文、明暗主题和窄屏发起
复制时的字体基线、换行和矩阵列对齐。

## 已明确、可直接实施的事项

### 临时同步说明

在“临时同步”控件旁增加问号说明：Agent 会在下一次常规轮询后建立一条由节点主动
发起、最长持续 10 分钟的 WebSocket 连接，并通过 Ping/Pong 保持连接；它只用于让
配置和任务更快同步，不改变现有 HTTP 协议，不要求节点开放端口，结束或失败后恢复
30 秒轮询。

### 节点列表降噪

Agent 列不再展示“源码”摘要和 `3/3` 等内部配置计数。列表只显示管理员能够理解并
采取行动的状态，例如在线状态、当前版本、可用更新、配置同步中或同步失败。

### 最新报告快速预览

当前公网 IP 旁提供“查看报告”操作，在弹窗中显示该 IP 最新成功报告。没有成功报告
时明确显示尚无可查看结果；入口不应伪造空报告。弹窗保留进入完整快照页面的操作。

### 立即探测确认

节点级立即探测确认框必须显示节点名称，并列出本次选择的公网 IP。确认只影响该次
任务，不改变周期探测开关。公网 IP 行内立即探测的目标已经确定，仍按现有规则直接
下发，不重复弹窗。

## 等待日志后诊断的事项

### ipapi 结果缺失

在日志能力完成前不把现象归因于额度、并发、超时或实现错误。复现时应关联同批次的
任务、公网 IP、请求开始与结束、HTTP 状态、限流响应头、超时阶段和重试结果。不得
在日志中记录 API Key；失败响应正文按已确认日志规则保存。

确认根因后再决定是否需要节点侧限速、Center 调度、带抖动重试、错误分类或用户可见
额度提示，不能仅以增加无界重试掩盖限制。

### NAT 判断与探测目标不一致

重点验证以下链路是否使用了同一组规范化公网 IP 身份：

- 网卡和默认路由形成隐藏发现路径；
- 轻量检查获得公网地址；
- Agent 上报当前地址集合；
- Center 合并并标记当前公网 IP；
- 立即探测任务冻结目标；
- Agent 将目标映射回可执行路径。

日志应能关联发现路径、公网 IP、地址族、代理、配置版本和任务 ID，但 Center 页面
继续只展示对用户有意义的公网出口，不泄露内部路径 UUID 或路由实现细节。
