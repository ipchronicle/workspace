# v0.1.1 线上问题与后续整改

## 文档状态

- 状态：讨论中
- 建立日期：2026-09-04
- 适用基线：已投入线上使用的 `v0.1.1`
- 目的：集中记录首个线上版本暴露的问题、处理优先级、依赖关系和待确认的
  产品或架构边界。

本文档是问题整改入口，不替代产品定义、系统架构或 ADR。经确认的长期决定应
同步写入相应权威文档；实现完成后应在本文件中记录验收状态。

## 优先级定义

- **P0：可观测性与结果可信度。** 当前会阻碍线上故障定位，或可能让管理员误判
  探测结果，应优先处理。
- **P1：身份连续性与操作正确性。** 不一定阻塞当前诊断，但会导致历史关联丢失、
  错误导航或高风险误操作。
- **P2：批量效率与界面可理解性。** 改善日常管理效率和信息层级，在 P0、P1
  边界明确后实施。

优先级表示处理顺序，不表示低优先级问题可以长期忽略。

## 建议处理顺序

1. 定义并实现 Agent 日志采集、传输、存储和 Center 查询能力。
2. 使用新增日志复现并定位 ipapi 缺失及公网 IP 发现、NAT 判断和任务目标不一致。
3. 统一报告值语义，修复页面与 PNG 输出；随后处理立即探测确认和返回路径。
4. 定义节点重装恢复身份的凭据和接管规则，并实现稳定版数据迁移与升级测试。
5. 重新定义首页关注项。
6. 实现节点多选及批量操作。
7. 完成临时同步说明、列表降噪和最近报告快速预览。

问题 2、6、7、9 可以与前述设计讨论并行准备，但不能绕过各自的验收要求。

## 需要先确认的设计

### 1. Agent 日志与中心查询

已确定的产品目标：

- Agent 应记录足以定位发现、探测、同步和外部请求失败原因的结构化日志。
- 管理员可以在 Center 中为节点选择日志等级。
- Agent 将符合当前等级的日志上报到 Center。
- Center 提供日志列表和筛选能力。

待确认边界：

- 等级建议使用 `error`、`warn`、`info`、`debug`，新节点默认 `info`。
- Center 是否只提供逐节点等级，或同时提供一个供新节点继承的全局默认等级。
- 外部请求失败至少区分 DNS、连接、TLS、超时、HTTP 状态、响应过大和响应
  格式错误；是否允许在 `debug` 中记录经过脱敏的请求目标和响应摘要。
- 日志不得包含 Agent Token、注册或恢复凭据、代理密码、API Key、敏感 URL
  查询参数和完整响应正文。
- Agent 离线期间的待上报日志必须使用有界缓存；需确认容量和溢出记录方式。
- Center 日志属于可丢弃的运维数据，建议使用独立 `logs.db`，避免日志写满影响
  `config.db`，也避免与业务历史保留策略混合；需确认保留方式。
- 建议筛选维度包括节点、时间、等级、组件、事件类型、任务、公网 IP、代理和
  关键词。
- 日志继续沿用 Agent 的纯出站通信，通过现有同步链路或专用批量 HTTP 接口上传，
  不为日志建立入站 Agent 接口。

持久化影响：Center 新日志库和 Agent 离线缓存都必须通过新迁移或向前兼容的
Agent 状态升级实现，不得修改 `v0.1.1` 已发布的迁移基线。

### 3. 首页“需要关注”

“需要关注”应只收录异常、失败或需要管理员采取行动的状态。建议收录：

- 应在线但已离线的节点；
- 配置同步失败或长时间未应用；
- 公网地址检查失败，或启用的节点没有可用公网 IP；
- 完整探测失败或部分失败；
- 内存不足导致完整探测自动暂停；
- Agent 更新失败；
- 任务长时间未接收、超时或执行失败；
- Agent 离线队列溢出造成的历史缺口；
- 报告字段格式异常；
- 通知持续投递失败；
- 存储空间或保留策略执行异常。

建议不作为关注项：

- NAT 路径本身；
- 正常的公网地址变化；
- 存在可用 Agent 更新；
- 下一次计划执行时间；
- 管理员主动禁用的节点、代理或公网 IP。

NAT 仍可作为公网 IP 的路径信息显示，但不应使用告警视觉或占用首页关注列表。
还需确认关注项何时进入、何时自动恢复，以及同类问题在首页按节点聚合还是逐条
展示。

### 4. 节点重装后的身份恢复

节点注册成功后，应提供该节点专属的安装命令。管理员在重装系统后使用该命令，
Agent 应恢复同一节点身份，并继续关联原有配置、历史和公网 IP，而不是创建新节点。

建议使用独立、可轮换的节点恢复凭据，不复用日常 Agent Token 或通用注册密钥。
待确认：

- 恢复凭据是长期可重复使用，还是成功恢复一次后自动轮换。
- 新 Agent 完成恢复后，旧 Agent Token 是否立即失效。
- 旧 Agent 仍在线时，是否允许新安装直接接管，或要求 Center 页面确认。
- 专属安装命令是否可以随时再次查看；如果只能重新生成，轮换时如何提示旧命令
  失效。
- 恢复行为保留哪些节点配置和运行状态，哪些主机能力必须由新 Agent 重新上报。

恢复凭据一旦泄露可能接管节点身份。Center 必须只保存不可逆校验值，并记录恢复、
轮换和失败尝试的安全事件。该功能涉及 `v0.1.1` 配置库和 Agent 本地状态，必须提供
向前迁移和升级测试。

### 5. 节点多选与批量操作

节点清单增加多选后显示批量操作条，至少支持批量更新 Agent 和批量完整探测。
批量操作不是事务：每个节点独立接受、跳过或失败，结果必须逐节点可见。

待确认：

- 批量探测默认选择每个节点“已启用且当前可用”的公网 IP，还是该节点全部当前
  可用公网 IP。
- 确认框是否允许逐节点展开并修改本次探测的公网 IP。
- 离线、禁用、忙碌、低内存或没有可用公网 IP 的节点如何展示和跳过。
- 批量更新是否只选择在线且存在可用更新的节点。
- 多选是否跨分页保留，页面刷新或筛选变化后如何处理已选择节点。

当前 UI 信息架构把跨节点批量操作限定为 Agent 更新。确认批量探测后，需要同步
修订该长期边界。

### 8. 返回来源上下文

建议采用以下统一规则：

- 应用内进入详情时显式携带来源路径及必要的筛选、分页和滚动上下文。
- 返回按钮优先返回显式来源，并恢复列表上下文。
- 直接打开 URL、刷新详情页或从新标签页进入时，返回到该资源的语义父页面。
- 不直接依赖裸 `history.back()`，避免返回登录页、站外页面或不可预测的历史项。

需全局盘点报告运行、报告快照、快照比较、公网 IP、节点详情和历史列表之间的
所有入口，形成一致的 fallback 关系。

### 12. 报告状态语义与 PNG

报告必须区分三个状态：

1. 数据源明确返回肯定结论；
2. 数据源明确返回否定结论；
3. 数据源没有返回结论，即 JSON `null`。

通用的“检测到/未检测到”不能准确表达所有字段。建议已知布尔字段使用与字段含义
匹配的肯定和否定文案；无法提供更自然文案时使用“是/否”。`null` 始终显示为
“无数据”或中性占位符，不能显示成否定结论，也不能被列为格式错误。

页面、PNG 导出、复制 PNG 和通知图片应共享同一套值格式化与状态色规则，避免相同
结果在不同载体中产生不同含义。PNG 修复至少要验证中文、英文、明暗主题、常见桌面
宽度和窄屏发起复制时的固定报告宽度，确保字体基线、换行和矩阵列对齐。

## 已明确、可直接实施的事项

### 临时同步说明

在“临时同步”控件旁增加问号说明：Agent 会在下一次常规轮询后建立一条由节点主动
发起、最长持续 10 分钟的 WebSocket 连接，并通过 Ping/Pong 保持连接；它只用于让
配置和任务更快同步，不改变现有 HTTP 协议，不要求节点开放端口，结束或失败后恢复
30 秒轮询。

### 节点列表降噪

Agent 列不再展示“源码”摘要和 `3/3` 等内部配置计数。列表只显示管理员能够理解并
采取行动的状态，例如在线状态、当前版本、可用更新、配置同步中或同步失败。

### 最新报告快速预览

当前公网 IP 旁提供“查看报告”操作，在弹窗中显示该 IP 最新成功报告。没有成功报告
时明确显示尚无可查看结果；入口不应伪造空报告。弹窗保留进入完整快照页面的操作。

### 立即探测确认

节点级立即探测确认框必须显示节点名称，并列出本次选择的公网 IP。确认只影响该次
任务，不改变周期探测开关。公网 IP 行内立即探测的目标已经确定，仍按现有规则直接
下发，不重复弹窗。

## 等待日志后诊断的事项

### ipapi 结果缺失

在日志能力完成前不把现象归因于额度、并发、超时或实现错误。复现时应关联同批次的
任务、公网 IP、请求开始与结束、HTTP 状态、限流响应头、超时阶段和重试结果。不得
在日志中记录 API Key 或完整响应正文。

确认根因后再决定是否需要节点侧限速、Center 调度、带抖动重试、错误分类或用户可见
额度提示，不能仅以增加无界重试掩盖限制。

### NAT 判断与探测目标不一致

重点验证以下链路是否使用了同一组规范化公网 IP 身份：

- 网卡和默认路由形成隐藏发现路径；
- 轻量检查获得公网地址；
- Agent 上报当前地址集合；
- Center 合并并标记当前公网 IP；
- 立即探测任务冻结目标；
- Agent 将目标映射回可执行路径。

日志应能关联发现路径、公网 IP、地址族、代理、配置版本和任务 ID，但 Center 页面
继续只展示对用户有意义的公网出口，不泄露内部路径 UUID 或路由实现细节。

## 验收与文档更新

- 每个问题应有针对其失败模式的自动化测试和必要的页面验证。
- 所有持久化变化必须验证从 `v0.1.1` 升级，且不能丢失配置、历史、节点身份、凭据
  引用或 Agent 离线队列。
- 日志和诊断不得暴露凭据、API Key 或敏感响应正文。
- 问题 1、4、5、8、12 的长期边界确认后，应更新产品定义、系统架构、UI 信息架构
  或建立相应 ADR。
- 涉及中英文界面的文案和公开文档必须同步维护。
- 实施前为每项问题补充明确的完成状态；验收通过后记录对应产品仓库版本或提交。
